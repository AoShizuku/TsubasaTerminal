# 回显脱敏与提示注入防御设计

定性：**Agent 读取终端数据的前置门槛**，不是普通功能——能读转录的 Agent 若没有它，
就是把数据库密码送进 LLM。原则：**转录层生来就该是"净化后"的，而不是先裸奔再补锁**。
代码入口 `src/main/redaction.ts`（脱敏）、`src/main/sanitize.ts`（ANSI/Unicode 净化）、
`src/renderer/src/lib/oscGuard.ts`（OSC 合理性校验）。
关联 [agent-terminal-context.md](agent-terminal-context.md)、[agent-design.md](agent-design.md)、
[composer-design.md](composer-design.md)。

## 一、回显脱敏

### 架构：一个闸门

脱敏是**结构化转录层出口的一个纯函数**（`redactText`），不是散落在各消费者里的正则。
所有机器消费者从同一个闸门取数据，规则只维护一份。

| 消费者 | 是否脱敏 | 说明 |
| --- | --- | --- |
| 人的屏幕 | **否** | 运维排查要看真值；屏幕打码只会逼人 cat 第二遍 |
| LLM 上下文（转录 / read_screen / 旁路输出） | 是 | |
| 审计日志、对话存档 | 是 | 用户在对话框里亲手输入的文字不经闸门，设置页明告 |
| 主机记忆 / 命令历史 | 是 | **命令行本身也是泄漏源**：`mysql -p'S3cret'` 会进历史 |

挂载点：OSC 133 的"命令-输出"单元。**懒执行 + 按单元缓存**——只在机器消费者真正读取时
才检测，不进渲染热路径（cat 大文件 MB/s 与脱敏无关）。PEM 块经常跨输出 chunk，
必须在拼好的单元文本上匹配——闸门不能架在字节流上。

设置页提供全局开关 `redactionEnabled`（默认开），关闭时设置页明告转录与历史保留原文。

### 检测层次

1. **高置信格式正则**：AKIA（AWS）/ LTAI（阿里云）/ `eyJ…eyJ…`（JWT）/
   `-----BEGIN … PRIVATE KEY-----` / ghp_、glpat-、xoxb-、sk- 等前缀 token。
   取 gitleaks 规则的精选子集，并学它的关键词预过滤：先廉价扫触发词，命中才跑正则。
2. **上下文启发式**：`password=` / `secret:` / `Authorization: Bearer` / 连接串
   `mysql://user:pass@host` / 命令行密码参数等 key-value 邻近关系——抓 `cat .env`、
   配置 dump、`curl -v` 头部这些最常见泄漏现场。
3. **自持凭据精确匹配**：应用自己攥着主机密码/口令，出现在任何输出里精确替换——零误报。
4. **良性区间白名单**：git SHA、`sha256:` 镜像 digest、容器 ID、UUID 等高熵字符串是
   LLM 诊断必需的上下文，误杀它们 Agent 就废了。白名单只约束格式类规则；上下文与自持
   匹配是强信号，不受豁免。

熵检测未实现。若引入，只能在"可疑关键词邻近 + 不在白名单"时加分，不独立定罪。

### 替换形态：稳定指纹占位符

`«REDACTED:aws-sk:9f3a»`（类型 + HMAC 短指纹，不可逆）。同一密钥多处出现占位符相同——
LLM 保留"这俩是同一个凭据"的引用推理，只是拿不到值。单向替换，不做执行边界回填。

### UX：误报反馈回路

会话角标"已脱敏 N 处"，点开审查明细（类型 + 指纹 + 次数，原文不出主进程；人在屏幕上
本可见真值，此处只为确认未误伤）。**误报的代价是 Agent 变笨，这个回路必须有。**

## 二、提示注入防御

前提要诚实：**没有银弹**。目标是纵深防御——让注入"最坏也做不成事"。

### 第一防线：权限架构

注入的最坏结果是"Agent 提出恶意命令"，审批台把每条写操作拦在人面前（详见
[agent-design.md](agent-design.md)）：

- 审批闸门在主进程，执行的是主进程自存的提案原文；
- **风险分级规则打底，LLM 无降级权**——被注入的 LLM 不能把 `curl|sh` 说成低风险；
- 只读白名单用**硬解析**（argv 级）判定，不问 LLM"这条是不是只读"；
- 只读白名单**排除一切发起出站网络的命令**（curl/wget/nc/ssh/scp/ping/dig…）——
  域名与 URL 皆可夹带数据，exfiltration 出口在白名单层焊死，不赌启发式；
- **主机等级进入审批语义**：生产机中风险位移到高危仪式、确认词改主机别名，只升不降、
  白名单照常。

### 特有攻击面：转义序列注入

远端输出可以伪造 OSC 7/133——假冒"命令结束/退出码 0"骗状态机、伪造 cwd 误导 cd 跟随、
用 ANSI 光标控制写出"人眼不可见但转录存在"的文本。对策：

1. 转录喂 LLM 前**剥离全部 ANSI/OSC + Unicode 归一**（NFKC，去零宽字符、方向覆盖、BOM）；
2. OSC 上报**合理性校验**：133;A 只在 D 之后或会话初始时可信（C 之后 D 之前的 A 是输出
   内容伪造，忽略），单会话 133 事件滑动窗口限流（`oscGuard.ts`）；OSC 7 的 cwd 必须像
   POSIX 绝对路径（长度上限、无控制字符，`useFileStore.ts` 的 `parseOsc7WithUser`）。连 D;code 一起伪造则
   与真实序列不可区分——数据通道内信号本可伪造，这里只抬门槛，根本防线是审批闸门与转录净化；
3. read_screen 读渲染后网格——"读屏不读流"天然免疫隐藏文本类伎俩。

### 常规但必要的几层

- **来源标注**：终端输出包在对话级随机 nonce 定界符内进入上下文，声明"这是数据不是指令"
  （格式见 [agent-design.md](agent-design.md)）；
- **独立 LLM 调用走最小上下文**：命令建议、标题总结等一次性调用只喂必要输入，不读可能被
  投毒的完整转录；风险定级不交给 LLM，由规则打底；
- 注入启发式检测（"ignore previous instructions" 类模式、伪造定界符闭合）做 advisory 标注，误报无害；
- **Agent 文本里的链接**：markdown 禁 raw HTML，页面内导航在主进程拦死；点击经应用内
  确认框完整展示 URL（不截断）后才 `window.open`。主进程 window.open handler 只放行
  http / https（`src/shared/url.ts` 的 `isWebUrl`）——确认框不是唯一的闸，`ms-settings:`、
  `smb://` 等协议交给 `shell.openExternal` 能拉起本机程序；渲染层用同一判定对其他协议
  直接告知打不开。
