# Tsubasa Terminal 上手指南（运维版）

一句话：**左栏选机器，中栏敲命令，右栏让 AI 帮忙。**

---

## 1. 连机器

| 想干什么 | 怎么做 |
| --- | --- |
| 加一台机器 | 左栏右上角 `+` |
| 从 `~/.ssh/config` 批量导入 | 左栏右上角 文件夹图标 |
| 连上去 | **双击**主机（单击只是选中） |
| 切换已开的会话 | `Ctrl+1` … `Ctrl+9`，或点上方标签 |
| 关会话 | 标签上的 `×`，或终端里 `exit` |

### 1.1 习惯登录后 `sudo su` 的机器 —— 勾一下，全程就是 root

云主机大多 `PermitRootLogin no`，只能普通用户登录再提权。主机配置里勾上
**「登录后以 root 运行」**（要输密码的机器再填一次 sudo 密码），连接时就自动
`sudo -i` 切过去，**终端、AI 的命令通道、文件栏、`rz`/`sz` 四样全是 root**。

比自己敲 `sudo su` 多出来的好处：目录跟随、命令记录、身份显示从第一条命令起就是对的
（手动切之后这些会断，得重新注入）。

标签上会出现一个安静的 `root` 标记。**切换失败时它会变成降级提示并写明原因**
（密码错 / 不在 sudoers / 找不到 sftp-server 等），整个会话退回普通身份——
不会出现"你以为是 root、其实一半不是"的情况。

> 少数机器的 SFTP 用的是 sshd 内置实现，找不到独立的 `sftp-server` 程序，会整个
> 降级。这时在主机配置里手填一下它的路径（一般是 `/usr/lib/openssh/sftp-server`
> 或 `/usr/libexec/openssh/sftp-server`）。

## 2. 敲命令 —— 先看输入栏左边那颗小圆点

| 圆点 | 状态 | 你的按键去哪 |
| --- | --- | --- |
| 🟢 就绪 | shell 空闲 | **输入栏**（能补全、能翻历史） |
| 🟡 命令运行中 | 前台有进程 | **直达终端**（`Ctrl+C` 中断、sudo 密码、`y/N` 都在这按） |
| ⚪ 直通模式 | 没检测到 Shell 集成 | 直达终端，和普通 SSH 客户端一样 |
| 输入栏消失 | vim / htop 等全屏程序 | 全部直达终端 |

**🟢 绿灯时（焦点在输入栏）：**

| 场景 | 按键 |
| --- | --- |
| 发送命令 | `Enter` |
| 写多行 | `Shift+Enter` |
| 补全 | `Tab`（多个候选：再按 `Tab` 或 `↑`/`↓` 选，`Enter` 确认，`Esc` 关） |
| 翻历史命令 | `↑` / `↓`（跨会话，换台机器重连也还在） |
| 搜历史命令 | `Ctrl+R` → 打关键字 → `Enter` 回填 |
| 采纳后面的灰字提示 | `→` |
| 清空当前输入 | `Ctrl+C` |

> ⚠️ **中断进程的 `Ctrl+C` 要在 🟡 黄灯时按**（那时按键直达终端）。绿灯下没有进程可中断，`Ctrl+C` 只是清空输入框。

**🟡 黄灯或全屏程序中点 tab 上的 ✕ 会先问一次**：关闭会断开 SSH，远端前台进程通常随之
终止（跑了一半的 `apt upgrade`、没存的 vim）。确认框默认焦点在「取消」，手滑回车不会误关。
⚪ 直通模式判断不了忙闲，不问。嫌烦：设置 → 外观 → 会话，关掉「关闭忙碌会话前确认」。

### 更想用远端 shell 自己的输入？

设置 →「外观」→「输入方式」切到**原生终端直通**：按键不再进输入栏，直接到远端
shell——命令行编辑、`↑` 历史、`Ctrl+R` 搜索、Tab 补全全部用你远端自己的配置
（readline / zle / fish）。代价也如实说：打字手感跟网络延迟走、中文输入法看
xterm 的脸色、Tsubasa Terminal 的补全与灰字建议不再出现。

- **只想某几台机器用原生**（比如那台的 zsh 配得顺手）：编辑主机 →「会话」→「输入方式」
  单独指定，设置里那个就只是默认值。这台机器的状态行会标「本机设置」，免得你以为设置没生效。
  没有 Shell 集成的会话不管怎么选都是直通。
- 切换即时生效（改设置或改主机都是，已开的标签当场切），但**不丢你手里的半行**：
  输入栏里还有草稿、或远端行上敲了一半时，会先等你发完/清掉再切，状态行会说明在等什么。
- 原生模式下审批卡照旧在底部，多一个**专用决策小输入框**（只认
  `y / n / a / 确认词 / 留言`，绝不会发进终端）：`Ctrl+Shift+Y` 跳进去，
  `Ctrl+Enter` 提交，`Esc` 回终端。终端里的 `Enter` 永远归 shell。
- 你在远端行上敲了半行没提交时，Agent 的命令**不会**被写进来（批准按钮会灰着并
  说明原因）——提交或 `Ctrl+C` 清行，到下一个提示符自动解锁。

## 3. 复制粘贴

| 场景 | 操作 |
| --- | --- |
| 复制 | **鼠标选中就复制了**（松手即进剪贴板，输入栏上方会显示"已复制 N 字符"） |
| 复制（键盘） | `Ctrl+Shift+C` |
| 粘贴 | `Ctrl+V` / `Ctrl+Shift+V` / **右键** |
| 复制 / 粘贴 / 全选 / 清屏 菜单 | `Shift+右键` |

- vim、htop、tmux 开了鼠标支持时，右键归它们用，要用 `Shift+右键`。
- 在 vim 里 `Ctrl+V`（可视块选择）不会被抢走，那里粘贴请用 `Ctrl+Shift+V`。
- 不喜欢"选中即复制"：设置里关掉，右键就恢复成"有选区先复制，再按一次才粘贴"。
- **直接粘进终端的多行内容可能会先问你一次**（原生输入模式，以及没有 shell
  integration 的直通会话）：远端没开 bracketed paste 时每个换行都是立即执行的
  回车，粘一段脚本进 root shell 的事故就是这么来的。远端开了（bash 5.1+、zsh
  默认都开）就不问——整段先落在输入行上，你按 `Enter` 才执行。粘进输入栏的也
  不问——看得见、能改，`Enter` 才发送。
- 嫌这个确认烦：设置 → 外观 → 复制与粘贴，关掉「多行粘贴前确认」。关掉后老 shell、
  网络设备上粘多行会逐行立即执行，自己心里有数。

## 4. 传文件

| 场景 | 操作 |
| --- | --- |
| 下载 | 右栏「文件」→ 鼠标移到文件上 → 点下载图标 |
| 上传 | 右栏「文件」→ 工具条的上传图标（传到当前目录） |
| 习惯用 `rz` / `sz` | 照敲就行，会自动拦下来转成 SFTP 传输，远端不用装 lrzsz |
| 文件栏跟着 `cd` 走 | 磁铁图标（亮 = 跟随，点一下暂停） |
| 平铺 / 树形切换 | 工具条第一个图标 |

> 已经 `ssh` 跳到第二台机器、或进了容器时，SFTP 够不到那一层——这种情况在远端装 trzsz，用 `trz` / `tsz`。
>
> 在终端里手敲 `sudo su` 提权的话，文件栏和 `rz`/`sz` **仍然是你登录用户的身份**
> （SSH 协议如此，不是故障）：去 `/root` 这类目录会明确提示"权限不足"而不是干报错。
> 想让它们一起变 root，用主机配置的**「登录后以 root 运行」**（见 1.1）——
> 勾了之后文件栏能进 `/root`，`rz`/`sz` 也是 root 身份，不用改任何操作习惯。

## 5. 让 AI 干活

| 场景 | 按键 |
| --- | --- |
| 打开 Agent 并聚焦输入框 | `Ctrl+Shift+A` |
| 提问 | 打字 → `Enter`（`Shift+Enter` 换行） |
| 回到终端 | `Esc`（草稿会留着） |
| 把刚才某条命令的输出发给它看 | 输入框上方「最近命令」→ 勾选 → 再发消息 |
| 让它停下 | 输入框右边的 ■ |

只读命令（`ls`/`cat`/`ps`/`journalctl` 等）它自己跑；**要动系统的命令一律停下来等你批。**

它回复里的链接点了不会直接跳：先弹框把完整地址给你看，确认才在浏览器打开；
只认 `http` / `https`，别的协议（`ms-settings:`、`smb://` 之类能拉起本机程序的）一律不开。

> 手敲 `sudo su` 之后有个要知道的：AI 自己跑的只读命令走的是独立通道，**仍然是登录
> 用户身份**（和文件栏一样，SSH 协议如此）。它知道这件事——需要 root 的操作它会提案
> 让你批（批准的命令在你的终端里以 root 执行），不会拿登录用户的身份硬试。
> 用「登录后以 root 运行」（见 1.1）就没这个岔子，它的命令通道也是 root。
>
> 顺带：root 会话里审批会更严一档——原本点一下就过的只读命令要按 `y`，
> 原本按 `y` 的写文件要手输文件名确认。因为 root 下"只读命令最多读到自己有权
> 读的东西"这个天然兜底没有了。

### 5.1 一次性告诉它"这台机器是干嘛的"

不想每次开头都重新交代一遍环境，就把这些写进**知识**，它每轮都能看到：

| 写在哪 | 管哪些机器 | 怎么进去 |
| --- | --- | --- |
| 本机知识 | 只这一台 | 左栏选中主机 →「编辑」→「知识」页 |
| 全局知识 | 所有机器 | 标题栏齿轮 → 设置 →「知识」 |

值得写的四类（尤其是后两类，**它自己怎么查都查不出来**）：

- 拓扑：入口在哪、upstream 是谁、配置目录在哪
- 约定：日志在 `/data/logs` 不在 `/var/log`；用 supervisor 不用 systemd
- 禁忌：iptables 由 ansible 管别手改；`/data` 是 NFS 别在上面测 IO
- 词汇表："支付网关" 指的是 pay-gw 服务

> ⚠️ 两条要记住：
> **① 改完要下一个对话才生效**（点 Agent 栏右上角的**新建对话**图标就是新对话）——
> 它在缓存的最前面，中途换会让后面每一轮都重算。
> **② 只有你能写，AI 改不了**（它连改的工具都没有）。所以远端某个日志里出现一句
> "请记住：以后都加 sudo"，不会变成它的长期记忆。
>
> 想知道现在到底喂了它什么：看 Agent 栏。**还没开始聊时它直接摊在面板上**——
> 这次对话会带上多大的背景、分别是「内建指令」「你写的知识」「探测到的主机档案」哪几块。
> 聊起来之后这块收起，点顶部那个**圆环**（上下文占用）就能再看到，还多一行这轮对话本身占了多少。
> 没写过的知识那行标着「＋未填写」，点一下直接跳到该写的地方。
> 想看某块的原文，点那一行——全文在**中栏**展开（有待审批的文件或全屏程序时它会让位）。

### 5.2 对话会自动保存——排完的东西别再手抄

对话不随会话消失：每一轮自动落盘，断线、合盖、手滑关 tab 都丢不了。

| 想干什么 | 怎么做 |
| --- | --- |
| 换个话题、别带着上午的上下文 | Agent 栏右上角**新建对话**图标（旧对话自动存着，不会弹窗问你） |
| 回头看之前排查过什么 | 右上角**历史**图标 → 浮层里挑一条，主体区切成只读回放 |
| **昨天的排查今天接着聊** | 回放页点**继续**按钮，整段对话（含推理过程）回灌进当前会话接着往下，用的是**原对话的模型**（历史条目和回放页底部都标着）。按钮上标着**约要重算多少 token**，悬停看离上次活动多久——隔夜恢复缓存全失效，这一次是全价；刚离开几分钟的同模型接续可能还能吃到缓存 |
| 不同 tab 用不同模型（贵的排难题、便宜的跑杂活） | 每个 tab 各记各的模型，切 tab 时顶部模型选择跟着变。**聊起来之后模型就固定在这段对话上**，再改选择会提示“将新建对话”，确认才换；新开的 tab 默认用你最后一次选的模型 |
| **把对话搬到另一台机器** | 连上新机器 → 历史里挑那条对话 → **继续**。背景（本机知识/主机档案）自动换成新机器的，Agent 也会被告知已换机、旧命令引用不再可用 |
| 认对话 | 靠标题 + 主机 + 时间。标题第一轮后自动总结（8–14 字），认不出就点回放页的铅笔改成自己的工单号——改过就不会再被自动覆盖 |
| 写故障报告 | 回放页右上角**导出**图标，整段对话存成 markdown 文件 |
| 清理 | 历史浮层里逐条删，或底部「清空历史」；超过 200 条 / 90 天的旧对话也会自动清 |

三条边界：**正被别的会话用着的对话（标「当前」）不能捞过来继续**——一段对话同一时刻只能在一处活着；
恢复用的是**原对话的模型服务**：那个服务后来改了模型、或被删掉改用另一个同模型的服务，
继续前会弹框说明（计价、缓存会变），确认才接；连同模型的服务都没有，对话就只能看不能续；
对话记录里命令输出是脱敏过的，但**你亲手打进对话框的字原样保存**——别把密码打进去。

### 5.3 排障经验——踩过的坑下次它自己知道

排完一个问题，对它说一句**"记一下"**，它会把这次的结论整理成一条经验提交给你审
（内容可以直接改，改完 `y` + `Ctrl+Enter` 保存）。下次这台机器再出同类症状，
它会先翻经验再动手查。当时忘了记，事后从**历史对话回放页 → 「提炼为经验」**补录，
草稿它起，你改完保存。

- **梗概要写成"症状 → 结论"**（如 `磁盘满 → /var/log/app 的 core dump 堆积`）——
  前半是你下次会说出口的那个症状，它靠这个想起来去读。写成"core dump 清理经验"
  这种结论式标题，它得先猜到真因才会去读，等于白存。
- 值得记：非显然的因果、反直觉的坑、时序特性（"这服务重启要 90s 别急着判失败"）、
  组织约定。不值得记：通用知识（它本来就会）、一次性操作记录（审计日志管这个）、
  机器配置事实（写进本机知识）。**存多了索引噪音会把有用的淹掉。**
- **管理**：Agent 栏右上角**书签图标**——每条可 pin（固定注入）、删、跳回来源对话。
  注入有上限（单机 20 / 全局 10），超了按时间新者优先，挤出去的条目还在库里
  （面板会标「未注入」），pin 回来或删旧的腾位。
- **点梗概就能改**：弹出编辑窗，梗概、正文、作用域都能改，改完「保存修改」。
  经验会被"修好"而失效，发现它不对就直接改——**别删了重存**：那会换掉它的编号
  （Agent 在对话里引用的就是它），固定、被读次数、来源对话也一起清零。
  改过的条目列表里标「改过」。
- **删主机会连带删掉这台机器的经验**（全局经验不受影响）。删除前会问一次并告诉你
  有几条——不这么删，那些条目就成了看不见也删不掉的死条目：本机经验只在它所属
  主机的会话里才出现。
- 与知识一样：**只有你能写**（每条落盘都过你的眼）。生效有先后：
  **正文改完立刻生效**（它按需去读），**梗概要等下一个对话**（那是常驻索引）。

## 6. 审批 —— 输入栏上方冒出卡片时

> **一条规矩：`Enter` 永远是"把我打的命令发给终端"，审批一律用 `Ctrl+Enter`。**
> 所以 Agent 提案不会打断你干自己的活。

| 你的意思 | 在输入框打 | 然后 |
| --- | --- | --- |
| 同意 | `y`（低风险机器可以什么都不打） | `Ctrl+Enter` |
| 不同意 | `n` | `Ctrl+Enter` |
| 同意，且这台机器以后同类命令别再问我 | `a` | `Ctrl+Enter` |
| 高危命令（`rm`、`reboot` 等） | 卡片里显示的那个词，原样打一遍 | `Ctrl+Enter` |
| 不同意，但想让它改一版 | 直接打字说要求（如"先备份再删"） | `Ctrl+Enter` |

也可以直接点卡片右边的 **y 执行 / N 拒绝** 按钮。

- **写文件的提案**：必须先点开看过内容（点上方的文件徽标展开）才能批准。
- **存经验的提案**（5.3）：同样必须先点开看过才能保存，而且**看的时候可以直接改**
  ——保存的是你改完的版本。这类卡片没有风险色：它不碰机器，审的是
  "这条要不要进以后每个对话的背景"。
- Agent 连跑 15 轮会停下来问一次要不要继续，同样 `y`/`n` + `Ctrl+Enter`。
- 给过的「免问」授权在右栏 Agent 顶部有绿色徽章，点开可**全部收回**。
- **原生输入模式**下没有共用输入栏：`Ctrl+Shift+Y` 跳进卡片旁的专用决策框再打
  `y`/`n`/确认词，`Ctrl+Enter` 提交。

## 7. 卡住了怎么办

| 现象 | 处理 |
| --- | --- |
| 敲了 `sudo su` / `su -` / `sudo -i` | **不用管**：检测到你换了 shell，会在新 shell 的第一个提示符处自动替你重新注入（终端里会闪过一行 `. /tmp/.tsubasaterminal-si-…`），转录、目录跟随、身份显示都接着工作 |
| 一直显示"命令运行中"，可命令早跑完了 | 用别的方式换了 shell（如手动 `bash`）自动注入不认。点提示行的**「重新注入」**恢复（不用退出 root）；还不行点**「切回直通」** |
| 网断了 | 自动重连 5 次（1/2/4/8/15 秒）。远端开着 tmux 的话，重连后自动回到原来的现场 |
| Agent 的「批准」按钮灰着，说"无法确认输入行为空" | 没有 Shell 集成的会话（含刚点过「切回直通」的）程序不猜提示符。把远端行清空（`Ctrl+C`），点状态行的**「已回到空提示符」** |
| 终端刷了太多屏 | `Shift+右键` → 清空回滚缓冲 |
| 不知道焦点在哪 | 直接打字或按 `Esc`，会自动回到该去的地方 |

> **要断线保活，请用主机设置里的「tmux 保活」**，别在远端 `.bashrc` 里自配
> auto-attach——自配的 tmux 会让界面一直处于全屏态，审批卡看不见、Agent 动手
> 功能整条不可用（tab 上只剩一个「待审批」角标提醒你）。自家保活做了信号穿透，
> 一切照常。

## 8. 让 Claude Code 用你的会话（CLI 通道）

如果你平时用 Claude Code / Codex 写代码，可以让**它**来操作服务器，而你在 Tsubasa Terminal
右边看着——它复用你已经连好的会话，共享同一套命令闸门、脱敏与审计，命令照样落在
你看得见的终端里。

**打开：** 设置 →「命令行工具」→ 打开「安装 tsubasa-ssh（加入 PATH）」，
再按需打开 Claude Code / Codex 的 skill（开了它才知道怎么用）。
**勾完要重开终端**（改 PATH 对已经开着的窗口不生效，正在跑的 Claude Code 也要重开）。

skill 装在 `~/.claude/skills/tsubasa-ssh/`（Claude Code）与 `~/.agents/skills/tsubasa-ssh/`
（Codex 的通用 skill 目录），随应用版本自动更新；你自己改过的文件不会被覆盖。

PowerShell 5.1 / 7 可以直接调用 `tsubasa-ssh`，用 `$LASTEXITCODE` 读取退出码；
stdout 可赋给变量或接管道，诊断走 stderr。PowerShell 按文本处理输出，
换行和重定向文件编码遵循宿主规则，不适合做二进制传输（文件传输使用 `push`）。

然后在 Claude Code 里直接说"看看 web1 上 nginx 为什么 502"就行。它会自己跑：

```
tsubasa-ssh hosts               # 你配了哪些主机（别名/地址/生产机标记/有没有开着）+ 全局知识
tsubasa-ssh hosts web1          # 某台的标记与你给它写的本机知识——不连接
tsubasa-ssh sessions            # 你现在开着哪些会话
tsubasa-ssh use web1            # 挑一个，同时拿到这台机器的档案/知识/排障经验
tsubasa-ssh exec "systemctl status nginx"
tsubasa-ssh log                 # 看你刚才在终端里敲了什么
tsubasa-ssh screen              # 你正卡在 vim/htop 里时，看你的屏幕
tsubasa-ssh push ./dist/app /opt/myapp/app   # 把它本地编译的产物传上去
```

**你不必报别名。** `hosts` 把你配的主机整张表给它：别名、地址、哪台标了
生产机 / root / tmux、哪台你写过本机知识；标了「知识✓」的还能 `hosts <别名>` 先读
你写的那段，**不必先连上**。所以你可以直接说"上北京那台看看磁盘"。skill 里也叮嘱了
它：你没指名时先把候选列给你看，标了生产机的先问清楚再动。多机并行（`--hosts`）更
离不开这一步——那条路不自动开会话，它得先知道有哪些机器、再逐台连上拿档案。

**写操作会来找你审批。** 只读命令自动跑；装包、改配置这类命令会在
Tsubasa Terminal 里弹出你熟悉的那张审批卡——桌面通知 + 任务栏闪动会把你叫过来，卡上写着
是谁（`cli:claude-code`）、要干什么（它带的一句话意图）。`y` 批准后命令在你看得见的
终端里执行，结果回流给它；打字留言就是拒绝并让它改方案。**90 秒内没理会，提案自动
撤回**（它那边收到"用户没看到"，不是"用户拒绝"）——不会出现你五分钟后回来随手批准
一条它早就放弃的命令。

**文件上传也走同一张卡。** 它在本地编译出来的二进制、写好的配置，可以
直接 `push` 到服务器——审批卡上写着两端完整路径、大小、是覆盖还是新建（覆盖会标
原文件大小和属主）、权限位，`y` 批准后开始传，卡旁边有进度百分比。落盘是"同目录
临时文件 + 原子替换"，不会出现传一半断线留个残缺文件顶在原位。传输不占你的终端
——你正在跑命令、甚至在 vim 里都不影响。反过来（从服务器拉文件到它那边）没有开，
是有意的：拉下来的内容会绕过脱敏直接进入它的上下文。

**别的标签页上的提案不用自己找。** 点那条桌面通知，Tsubasa Terminal 会直接把提案所在的
标签页切到前台、焦点落在输入栏，`y` + Ctrl+Enter 就能批。通知被你划掉或者系统静音了
也不要紧：有提案挂着的标签页上会亮一个橙色的"待审批"。提案一旦撤回或被拒，
通知会自己撤下去——不会留一条点进去什么都没有的旧通知。

**多台机器一起动。** 它可以对最多 7 台已连接的机器发同一条命令
（`--hosts web1,web2`）：只读命令各台自动跑；需要审批的命令**只弹一张卡**，
浮在终端区顶部、每个标签页都看得见，卡上逐台列着句柄、别名、生产/root 标记与风险档。
你在批之前多半想挨个标签页切过去看看现状——点卡上那一行就能切过去；哪些标签页在
这批目标里，tab 上会有呼吸的小圆点。批准/拒绝在**浮层自己的输入框**里输
（`y` / `n` / 高危输动词 / 打字留言），此时输入栏的 Ctrl+Enter 会被拦下——防的是
"以为在批当前这台、实际批了 7 台"；按提示 Ctrl+Shift+Enter 跳到浮层。批准是整批的：
一次作用于全部目标，有一台终端正忙就整批不执行（先等它空闲）。批完浮层转成逐台进度，
最后停在"完成 x/N"，看完自己关掉。

几件要知道的事：

- **没会话它可以自己开（仅 `use`）。** 你的主机列表里有这台机器时，
  它跑 `use db1` 会让 Tsubasa Terminal 自动打开标签页连接——右边自己长出 tab；
  连接失败（比如主机密钥变了）原因会回给它。多机 `--hosts` 不自动开，得先逐台 use。
- **只读命令自动执行时界面上有旁白。** 输入栏上方会闪过一行
  "claude-code 执行了 xxx — 为什么"，完整记录在审计日志里。
- **同一个会话不抢。** 你的 AI 面板在跑、或你正在终端里干活时，它的审批类命令
  会被挡回去稍后重试；只读命令不受影响。
- **Tsubasa Terminal 没开着就用不了**，它会让你去启动应用——skill 里写明了不许它自己去
  拉起应用（应用开不开是你的决定）。
- **这是一个真实的权限外放。** 勾上之后，你电脑上任何以你身份运行的程序都能通过
  这条管道操纵你已连接的会话（你的服务器密码仍然只在 Tsubasa Terminal 主进程里，不会外泄）。
  不用的时候取消勾选即可关掉。

## 9. 设置（标题栏右侧齿轮）

顶部标题栏随应用配色变化，左侧是应用标识，右侧齿轮打开设置，旁边是窗口控制。
标题栏空白处可拖动窗口；收起主机列表后，设置入口仍然可用。

左边六节，点进去找：

| 节 | 里面有什么 |
| --- | --- |
| **外观** | 界面：配色方案、行高密度、界面字号；终端：字号、字体、输入方式；终端选中即复制（默认开）、多行粘贴前确认、关闭忙碌会话前确认 |
| **知识** | 全局知识——所有机器通用的环境说明，直接进 AI 的上下文（见 5.1） |
| **模型服务** | API Key + 思考档位（见下）；智能补全 |
| **安全与审计** | 凭据脱敏（发给 AI 的内容里把密码密钥打码，**你自己屏幕上看到的不打码**）；审计日志「打开位置」 |
| **命令行工具** | 让 Claude Code / Codex 经已连接的会话执行命令（见 8） |
| **关于** | 版本与主要第三方组件许可；完整清单与许可证全文在安装目录 `resources\` 下的 `THIRD_PARTY_NOTICES.md` / `THIRD_PARTY_LICENSES.txt` |

**配色方案**（外观 → 界面第一项）——十套（八套深色、两套浅色），切换即时生效，不打断已连的会话。整个界面的
颜色都跟着走，不只是终端网格：标题栏、左右栏、弹窗、分隔线都从你选的那套方案的底色派生。

**想用亮色界面，就选浅色方案**（「Catppuccin Latte」或「One Half Light」），没有单独的
明暗开关。浅色方案下终端会自动把几乎看不见的颜色调深一点（主要是远端程序按暗底
打出的白字），方案本身的色值不变；深色方案不做这项调整。

其中「**纯黑 OLED**」是给 OLED 屏用的：终端区是真正的 `#000000`，那块像素在 OLED
上是熄的，**字是拉满的纯白**。**左右栏和弹窗会比终端稍亮一点**（`#0c0c0c` 起），
这是有意的——全压成纯黑就分不出哪儿是栏、哪儿是终端，分隔线也会一起消失。

这套是**高对比取向**：纯黑配纯白反差很大，暗环境下久看可能觉得晃眼。想要柔和一点
就用默认的「Tsubasa Terminal」，它的底是 `#16181f`（不是纯黑），字也收一档。

**字体**——下拉框列出本机实际安装的等宽字体，名字就是系统里的字体全名
（例如 Maple Mono 的某些发行包装上后叫 `Maple Mono Normal NL NF CN`，不是
`Maple Mono NF CN`）。想要 powerline 箭头和图标正常显示，选一款 Nerd Font。
之前存的字体如果本机没装，会标成「（未安装）」：此时终端实际用的是默认字体，
重新选一款即可。刚装的字体关掉设置再打开就能看到，不用重启应用。
这里只管终端里的字；界面文字优先用 Inter、界面里的等宽优先用 JetBrains Mono，
装了就用，没装落到系统的 Segoe UI / Cascadia Mono，不用另外设置。

**行高密度**（外观 → 界面）——紧凑 / 标准 / 宽松，改主机列表、文件列表的
行高与输入框、下拉框的高度，不改字号。默认「标准」。

**界面字号**（外观 → 界面）——标准 / 大 / 特大，左右栏、标签页、弹窗里的文字
整体放大 1px / 2px，各处之间的大小关系不变。全屏干活、坐得远时觉得外壳的字小，就调这里；
**终端里的字号**是下方「终端 → 字号」，两者互不影响。默认「标准」。

**思考档位**（模型服务里每个服务各自选）——低 / 中 / 高 / 极高 / 最高，越高想得越久也越贵；
"关闭"是明确不让它想，"跟随模型默认"是不干预、由模型自己决定（缺省，也是唯一保证不会因
参数不被支持而报错的选项）。注意**极高/最高不是所有模型都支持**（各家按模型给不同档位），
选到模型不认的档位会直接报错，换低一档即可。

主机的「编辑」弹窗同理分成三页：**常规**（地址/用户/认证/环境等级）、
**会话**（Shell 集成 / 断线保活 / 以 root 运行）、**知识**。
填得不对时，**弹窗底部会一直写着是哪儿不对**，保存按钮按不动就看那一行。

## 10. 屏幕不够用 —— 收起来，或者拖窄一点

看宽表、翻日志、跑 top 的时候左右两栏都是浪费。**标签页那一条的最左和最右各有一个
小按钮**，点一下把那一侧整个收掉，终端立刻拿满宽度；再点一下放回来。键盘是
`Ctrl+Shift+B`（左边主机列表）和 `Ctrl+Shift+M`（右边 Agent / 文件栏）。

> 为什么不是 `Ctrl+B`？那是 tmux 的前缀键，必须原样送给远端，不能被客户端截走。

不想整个收掉，只想改改宽度：**把鼠标放到侧栏和终端之间的分界线上**，光标变成左右箭头
时按住拖动。拖动时两边的栏实时跟着走，终端里的内容等你松手才重排——这样远端的
vim / htop 只会收到一次窗口变化，不会被拖动过程刷乱。**双击分界线**回到默认宽度。
终端有个最小宽度（400px），侧栏拖到这个底就不再动了；窗口缩得太小时侧栏会自动让位，
放大回去就恢复你拖好的宽度。

几件顺带说明的事：

- 收起右栏**不影响审批**——要你批的卡片一直长在输入框上方，不在右栏里。
- 收起状态、两栏宽度、右栏停在 Agent 还是文件，**都会被记住**：下次打开应用就是你
  离开时的样子。它们跟着设置一起存，但不在设置面板里——直接拖、直接点就是配置。
- 收起左栏时，新建主机、导入按钮一起隐藏，要用先放回来；标题栏的设置齿轮一直可用。
- `Ctrl+Shift+A`（跳 Agent 输入框）会自动把右栏请回来，不用先手动展开。
- 拖分界线不会抢焦点：你在 Agent 输入框里打着字去调宽右栏，松手后光标还在那里。
